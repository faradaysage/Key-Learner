# Unity asset pipeline

The project contains all runtime art locally. Building from the checkout does not download assets and does not require Blender. Third-party source assets live in `UnityPort/Assets/ThirdParty`; their licenses and exact file hashes are recorded in [the asset ledger](../THIRD_PARTY_ASSETS.md) and [`ASSET_MANIFEST.json`](../UnityPort/Assets/ThirdParty/ASSET_MANIFEST.json). Paths beginning with `Assets/` below are relative to `UnityPort/`; `scripts/`, `Studio/`, `Shared/` and `artifacts/` paths are relative to the repository root.

Run **KeyLearner > Configure project and content** in the selected Unity Editor, or call `KeyLearner.Unity.Editor.ProjectSetup.Configure`. Its `ContentBuilder.Build()` adapts the source meshes into generated materials/prefabs and writes `Resources/ContentLibrary.asset`. Use `ContentLibrary.Spawn(category, index, parent, position, height, yaw)` from a game to select a reusable model. The requested height is in game units; the model's real proportions remain intact. Heroes and swimming animals have a centered wrapper pivot; scenery and cars have a bottom pivot. Yaw metadata aligns the model's nose with local +Z. Each item records its complete source `Size`. Use `SpawnWidth(category, index, parent, position, width, yaw)` for paths, driveways, pebbles and broad ground details: it scales uniformly by authored X width before yaw, retaining the source aspect ratio and thinness. Height-normalizing a .01-unit driveway would otherwise turn it into a giant platform.

The generated library uses explicit categories: tree, dead-tree, bush, flower, rock, pebble, path, driveway, fence, planter, house, commercial, building-detail, parasol, farm-building, farm-small, well, landmark, roadfurniture, construction, sign-panel, utility, car, bird, dolphin, fish, whale, shark, ray, coral, seaweed and prop. `rock` contains only the three substantial boulder meshes, and `tree` contains only living trees. Complete lamps and mounted signs are `roadfurniture`; loose panels and building attachments are separate roles. `prop` is reserved for standalone miscellaneous objects. Adding another verified pack requires a classification rule in `ContentBuilder`, source-specific texture mapping if the source needs it, and a license-ledger entry. Gameplay should use this library instead of reaching into third-party filenames. Future content can later use more detailed catalog metadata without changing the preserved game models.

Generated files under `KeyLearner/Generated` and `KeyLearner/Resources/World` are builder-owned and refreshed in place. Their existing Unity GUIDs are retained. Keep manual material/prefab variants outside those generated paths. The builder never edits the original model's mesh, UVs, bones or animation. It instantiates a wrapper, measures static geometry and actual skinned vertices across the locomotion cycle, removes incidental source lights/cameras/colliders, and remaps source material slots. The original Kenney palette textures and Quaternius cutout foliage are retained. Suburban house families use the four supplied original palette variants deterministically, preserving UV color regions while varying roof/wall colors. Reef colors come from the actual embedded atlas. The six coral source files contain 35 individual organism objects arranged in display rows. The builder creates a prefab for each intact authored object and interleaves coral families before palette variants in the catalog; it does not split individual branches or retain the display rows as scenery. Animated normalization uses a separate Pivot transform so source root animation cannot overwrite placement. Skinned bounds use `BakeMesh(mesh, true)` before `TransformPoint` to compensate source renderer scale exactly once; `false` produces incorrect dimensions for these FBX rigs. Culling bounds are recorded in root-bone coordinates across the selected locomotion cycle. Isolated Unity renders verified bird and dolphin visibility after this correction.

Animal prefabs use Legacy Animation with the source locomotion clip selected explicitly. Dolphin/whale/shark/ray use Swim; cute fish use Swimming_Normal; the bird's exported Scene take is named Flight by the Unity importer while retaining its original 1-30 frame take binding. Hostile/death clips are never selected. `SourcePropMotion` rotates the real wheel meshes using traveled distance and the real windmill blade meshes around their original hubs. Its `MotionScale` can reduce scenery movement for Gentle Motion.

`ExplorerCloudLayer.Create(parent, camera, gentleMotion)` adds a bounded set of soft cloud particles. `KeyLearner/SeabedCaustics` shades seabed vertex colors with restrained moving caustics. These effects are procedural because clouds/light patterns are appropriate generated effects, and they do not replace recognizable models. Keep both shaders in the build's explicit shader list when using Shader.Find.

Land scenery is composed by `LandEnvironmentComposer.Populate(services, parent, start, index, race, centerX)`. It places only licensed models; terrain, road, water, player movement and streaming belong to the explorer host. Deterministic world-band centers and chapter indices choose forest clearings, farms, village courtyards, urban frontages and distant skylines, shore overlooks, mountain outcrops and tundra groves. Buildings reserve footprints before vegetation placement, and race scenery observes road clearance. Forest edges extend through the chapter instead of repeating isolated circular groves; mixed species, canopy heights, shrubs, ferns, grouped flowers and boulders form near and middle layers. City and town frontages use connected source paving, footprint-based building setbacks, paths to doors and correctly scaled garden fences. Pavement follows ground slope, and rock outcrops align to the terrain normal with their lower portion embedded for ground contact. Each chapter caps trees at 88 and small plant details at 72. Selected forest/lake chapters contain 3–5 source-rigged birds with offset animation timing; `SceneryFlight` owns their bounded orbit and honors Gentle Motion. Scenery is destroyed with its streamed parent. Keep region composition changes here instead of adding game logic or learning rules to the content builder.

## Generated files and safe authoring

| Location | Ownership and rebuild behavior |
| --- | --- |
| `Assets/ThirdParty/<pack>/Models`, textures and original notices | Canonical licensed source files. `ContentBuilder` reads these without rewriting the FBX, PNG, mesh, UV, rig or original notice bytes. Re-acquisition/conversion scripts intentionally replace their outputs only when run separately. Preserve source hashes and licenses when updating them. |
| Source model and texture `.meta` files | Unity asset identities and import settings. The builder controls the documented animation, texture, camera/light and selected boulder-readability settings. Commit stable `.meta` files; use Editor importer APIs instead of editing them as text. |
| `Assets/KeyLearner/Resources/World/*.prefab` | Generated and saved in place on every content rebuild. Prefabs under this entire folder that are no longer in the generated catalog are deleted. Do not keep custom prefabs here. |
| `Assets/KeyLearner/Generated/Materials/*.mat` | Generated materials with stable GUIDs. Shader, texture, color, normal, cutout and related settings are reapplied on rebuild. Old unused material files are currently retained. Manual adjustments at these paths are overwritten. |
| `Assets/KeyLearner/Resources/ContentLibrary.asset` | The asset is loaded in place. Its `Items` array is regenerated; its `AuthoredItems` array is preserved. Edit `AuthoredItems` for custom replacements/additions, rather than editing `Items`. |
| `Assets/KeyLearner/Authored/` | Recommended artist-owned location for custom prefabs, materials, textures, animation and volume profiles. ContentBuilder never writes here. Reference authored models through `ContentLibrary.AuthoredItems`. |
| `Assets/KeyLearner/Scenes/KeyLearner.unity` | Created only if absent. Subsequent Configure runs preserve the existing scene. The camera/game host still applies gameplay-specific runtime settings. |
| `Assets/KeyLearner/Generated/KeyLearnerVolume.asset` | Initial-scene defaults. Configure preserves it when the main scene already exists; recreating an absent main scene reapplies its default bloom/color/tone settings. Use an authored profile outside Generated for deliberate custom grading. |
| `Assets/ThirdParty/ASSET_MANIFEST.json`, `Assets/KeyLearner/Resources/AssetCredits.txt`, `Assets/StreamingAssets/Notices/` | Distributed provenance/credit outputs of `scripts/write-asset-manifest.py`. Edit the canonical root ledger, verified original notices, or credits text in that script, then regenerate these outputs. |
| `Assets/KeyLearner/Runtime`, `Editor`, and `Shaders` source files | Hand-authored implementation. Configuration does not generate or overwrite this source. |
| `artifacts/unity/content-import-report.txt` | Generated import/bounds/clip evidence, outside runtime Assets. Replaced on rebuild. |

`ProjectSetup.Configure` also reapplies selected player/quality/graphics and URP settings. Change those defaults in `ProjectSetup.cs` when they should survive configuration. A normal Windows build uses the existing scene and catalog; it does not fetch art or run the optional acquisition scripts.

To replace a model, duplicate its generated prefab into `Assets/KeyLearner/Authored/`, duplicate any materials that you intend to change into that folder, and assign the material copies to the custom prefab. Add an `AuthoredItems` entry to `ContentLibrary.asset` with the exact original stable `Id`, desired category and custom prefab. Copy the original `Height`, `Size` and `Yaw` metadata when proportions/pivot are unchanged. If the art's dimensions change, update this metadata in source units: the spawn API scales uniformly by `Height` or source X `Size`, so arbitrary metadata will distort intended placement. Keep a centered pivot for swimming/flying animals, a bottom pivot for scenery/cars, and local +Z as the forward axis (or record the correction in `Yaw`). Preserve the actual locomotion component/rig on animated replacements.

An authored entry with a matching ID replaces the generated item in its existing position; a new ID appends a new item. Category changes are respected. The last authored entry wins if an ID appears twice, so use unique IDs for clarity. Empty IDs, empty categories and unassigned prefabs are ignored to keep unfinished inspector rows from hiding working content. Rebuilding updates generated defaults while preserving this authored overlay and its prefab/material files. Replacing an asset never removes the need to record its license and distribution notices. An isolated actual-Unity verification exercised replacement order, new IDs, incomplete rows, metadata selection, preservation across `SetItems`, cache invalidation, duplicate-ID/category behavior and compatibility with an absent authored array; all seven assertions passed (`artifacts/unity-asset-research/authored-overrides-verification.txt`).

## Region preview acceptance

The domain's `ExplorerWorld.RegionLength` is 950 units. `Area(z)` selects `floor(-z / 950)` modulo seven. Terrain blends from the previous region during the first 190 units, so region midpoints provide a useful composition check:

| Region | Preview distance | Recommended inspection |
| --- | ---: | --- |
| Forest | 475 | Connected canopy, intentional clearings, visible understory and animated birds; no learning-target occlusion. |
| Lakes | 1425 | Water openings, wooded headlands, shoreline planting and overlooks; no submerged houses. |
| Mountains | 2375 | Pine/outcrop silhouettes against elevation, distant atmosphere, and road clearance. |
| City | 3325 | Frontage, planted breaks, readable skyline and correctly proportioned street furniture. |
| River | 4275 | Clear water vista, irregular banks and vegetation rooted on land. |
| Town | 5225 | Distinct courtyards, correctly oriented driveways/fences, parked vehicles and farms. |
| Tundra | 6175 | Sparse vegetation appropriate to the region, distant rocky silhouettes and visible terrain transitions. |

Use disposable preview launches with `--preview-distance <value>` and the desired explorer mode. This option is restricted to preview sessions. Inspect both Sky Speller's elevated view and Letter Racer's road-level camera, because a grove that reads well from above can block the horizon at driver height. Capture actual player screenshots, inspect logs, and compare repeated chapters and neighboring horizontal world bands. Include a moving sample for the source wing/flipper cycles, wheels, windmills and the Gentle Motion setting. Rooted coral contact and marine composition are separate Ocean Speller acceptance checks. A successful import or isolated model render does not replace these gameplay checks.

## Optional re-acquisition and conversion

Original archives are staged outside Assets in ignored `_asset_downloads`. They are unnecessary for normal builds. Run the following commands from the repository root, in order, only when deliberately updating source art. Review current licensing and downloaded contents before accepting new hashes. The public fish/farm downloader depends on the license files staged by step 1; the reef importer expects the exact user-supplied archive names in its source.

The supplied `Mushroom by Quaternius - aOW08oSrd4.zip` was also checked. Its only file, `Mushroom_Common.fbx`, contains the same artwork as the existing creator-pack catalog entry `QuaterniusNature_Mushroom_Common` (`flower`). Both imports have 490 vertices, 440 polygons and identical UV data; corresponding geometry differs by at most 0.000000174 world units from export precision. The embedded 1024×1024 texture has pixel-identical RGBA content to the existing source texture. The different archive/FBX/PNG byte hashes reflect embedding/export/encoding differences. The ZIP contains no separate license notice; the verified creator Nature pack supplies the existing CC0 notice. No duplicate model was imported. The comparison report is `artifacts/unity-asset-research/mushroom-inbox-check/geometry-comparison.json`; archive SHA-256 is `51b2158dbee907753d1d89f65c355d15d5c42d9252e1ed171960a4ee0dd2d034`.

1. `python scripts/stage-unity-assets.py` downloads the fixed creator-published archive sources and stages selected FBXs/textures/notices.
2. `python scripts/download-curated-public-assets.py` downloads the twelve selected fish and nine farm models from the creator's public shared files. It never signs in or reads account credentials.
3. Run the discovered local Blender executable with `--background --disable-autoexec --python scripts/convert-bird-asset.py` to reproduce the bird FBX. This conversion was validated with installed Blender 4.3.2; no .blend asset is imported by Unity.
4. With the user-supplied archives present, `python scripts/import-manual-reef-assets.py` imports the manual reef FBXs and supplied license notices. Run the discovered Blender with `--background --disable-autoexec --python scripts/extract-embedded-reef-textures.py`, then `python scripts/extract-seaweed-texture.py`, to recover the original embedded image bytes. No Poly Pizza page is accessed automatically.
5. `python scripts/write-asset-manifest.py` records actual imported files and updates the distributed notices and accessible credits text. It requires all three provenance inputs in `_asset_downloads`: `import-manifest.json`, `public-file-manifest.json` and `inbox-import-manifest.json`, produced by steps 1, 2 and 4. The script does not download missing inputs.
6. Rebuild the content library in Unity, inspect `artifacts/unity/content-import-report.txt`, and review actual gameplay cameras before accepting the updated content.

For a ledger or credit-text update that keeps the existing source art, recover those three provenance inputs from the committed manifest before running step 5. This avoids downloading the archives again. It preserves the original acquisition metadata while step 5 recalculates the current source-file hashes; review the resulting diff before accepting it.

```powershell
@'
import json
from pathlib import Path
stage = Path('_asset_downloads')
stage.mkdir(exist_ok=True)
manifest = json.loads(Path('UnityPort/Assets/ThirdParty/ASSET_MANIFEST.json').read_text(encoding='utf-8'))
inputs = {'source_archives': 'import-manifest.json',
          'public_creator_files': 'public-file-manifest.json',
          'manual_archives': 'inbox-import-manifest.json'}
for key, filename in inputs.items():
    (stage / filename).write_text(json.dumps(manifest[key], indent=2), encoding='utf-8')
'@ | python -
python scripts/write-asset-manifest.py
```

One-off inspection/render/patch-preparation scripts are archived in ignored `artifacts/unity-asset-research`; their source inspection reports and bird candidate renders are in ignored `_asset_downloads`. These are historical diagnostics rather than supported build tools; they are not proof of final Unity visual quality. Final gameplay screenshot and performance acceptance is documented separately in the migration report.
